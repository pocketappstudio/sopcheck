## Guideline findings (App Store Review Guidelines, last updated Oct 16, 2026: https://developer.apple.com/app-store/review/guidelines/)
- **4.2 Minimum functionality**: must be more than a repackaged website. Mitigation: bundled offline app, camera scan + on-device OCR, camera task photos, haptics, offline mode, native splash, push-ready.
- **2.2 / demos**: apps must be complete, not demos or trials. The current in-app backend uses sample data per device, so for submission it should point at a real hosted backend (or be clearly a full local single-device tool). Highest-risk item.
- **3.1.1 In-app purchase**: unlocking features or subscriptions in the app must use IAP; **license keys are explicitly not allowed** as an unlock mechanism. The Manager > Billing "paste Gumroad license key" screen and "Buy on Gumroad" buttons must be hidden in the iOS build (web keeps them).
- **3.1.3(c) Enterprise services**: apps sold directly to organizations for their employees may let those users access previously purchased subscriptions; consumer/single-user sales must use IAP. **3.1.3(b) Multiplatform**: access to web-bought subscriptions is allowed if also offered as IAP. **3.1.1(a)**: on the United States storefront, external purchase links/buttons are now allowed without an entitlement.
- **5.1.1(v)**: apps with account creation must offer in-app account deletion. SOPCheck already has self-service delete account and delete workspace on the Account page.
- **5.1.2(i)**: must clearly disclose and get explicit permission before sharing personal data with **third-party AI**. Add an in-app consent before the first AI parse (the acceptance gate already discloses OpenAI processing; Apple wants explicit permission).
- **1.2 User-generated / AI content apps**: content reporting, blocking and published contact info are for social/UGC apps; SOPCheck content is private to a company workspace, so low risk. Contact info can be the Gumroad page / support URL (no email).
- Google Play: Payments policy (https://support.google.com/googleplay/android-developer/answer/9858738) requires Play Billing for digital subscriptions, with US exceptions for alternative billing/external links; Play also requires in-app and web account deletion (User Data policy) and a Data safety form.

## Recommended iOS monetization
1. **Launch: free app, sign in to an existing workspace + the existing 14-day in-app trial; no purchase UI in the iOS app** (hide license-key and Gumroad buttons in the native build only; web unchanged). Organizations buy on the web (Gumroad), like the 3.1.3(c) enterprise / multiplatform model. On the US storefront a "Manage plan on the web" link is allowed (3.1.1(a)).
2. If Apple rejects under 3.1.1 or for consumer sales: add auto-renewing IAP subscriptions (Starter/Team) with StoreKit (cordova-plugin-purchase, already used by Buck Ledger) and server receipt validation; price IAP to cover Apple's 15% (small business program) fee.
Android: same approach (free app, web billing in the US with external-offer rules, or Play Billing).

## Production backend hosting (needed before store submission)
- **Recommended now: container host for the existing FastAPI app, unchanged** (repo already has Dockerfile, fly.toml, render.yaml, Postgres support): e.g. Fly.io or Render paid tier (~US$5-15/mo + Postgres), native Tesseract OCR works, background purge thread works.
- **Cloudflare (existing account) is feasible but a port**: Python Workers are GA and run FastAPI (https://blog.cloudflare.com/python-workers-ga/), D1 from Python (https://developers.cloudflare.com/d1/examples/query-d1-from-python-workers/), R2 for files. Needs Workers Paid (US$5/mo; free plan is 10 ms CPU per request, paid up to 5 min, https://developers.cloudflare.com/workers/platform/limits/). Work: SQLAlchemy to D1 (no native driver; rewrite queries or use a D1 adapter), uploads/photos to R2, no Tesseract (use the app's on-device OCR or the AI proxy), background purge to a Cron Trigger, bcrypt CPU cost. Estimate: several days plus testing. Good long-term fit (one vendor, low cost), not the fastest path.
